Motion2Scene 研究续稿：让压缩保留可通行动作，让生成提前响应几何约束

研究日期：2026-09-19。本文接续用户提供的两份材料。初次撰写时已检查相关论文正文及 SONIC 公开代码，尚未进行数据审计或训练。后续工作已完成两轮合成表示实验和本地参考数据检查，见 PILOT_V1_RESULT.md、BOUNDARY_V2_RESULT_zh.md 与 LOCAL_DATA_INVENTORY.md；仍未完成 MTC 原始数据训练或闭环执行。本文以下公式中的设计与推论不应被当作已获得的性能结果。

我的建议是保留 conditional flow matching，但把主问题收敛为：在相同数据、表示容量和推理预算下，能否保留会改变全身可通行性的局部几何，并在最后可调整时刻之前生成合适的动作？这比“FM 生成 motion token，再交给 SONIC”更具体，也更容易被实验推翻或支持。

现有工作已经覆盖了这条系统路线的大部分。PASSAGE 是场景条件 FM 与感知 tracker 的直接参照；TANGO 将 FM 生成的全身参考交给 SONIC。新的方案需要解释自己对信息、时序或执行误差的处理带来什么增益，不能用组件组合本身声称首次。[PASSAGE](https://arxiv.org/html/2609.18732v1)、[TANGO](https://arxiv.org/html/2609.09158v1)

对原材料的四个实质性推进是：用动作兼容性而非平均重建误差定义压缩质量；用延迟调整的反事实识别关键事件；让 attention 查询身体扫过的区域而非单个关节点；把时间相关的 FM 源分布与最终结果的几何约束分开研究。

1. 先确定研究对象与执行接口。

设机器人测量历史为 h，当前可用导航条件为 g，因果观测地图为 S_obs，已经承诺执行的参考前缀为 P。第一版学习

$$
p_\theta(M\mid C),\qquad C=(h,g,S_{obs},P).
$$

M 是未来 H 个时刻的连续机器人参考。一个可诊断的内部形式是当前机器人坐标系中的 root 位置、连续旋转表示和关节角；需要的速度由同一个物理时间参数化计算或进行一致性约束。最终字段以选定 SONIC adapter 为准，不能把这个内部形式当作已验证的原生协议。

必须区分 Transformer embedding、可解码的 motion latent、SONIC native token 和实际执行动作。公开 SONIC 实现的 encode 可以返回量化前 latent 或量化后的 codes；decode 使用指定 decoder 的输入，其中可以包括本体状态。其公开 VLA 路径还具体区分 motion token 与手部关节。不同 checkpoint 的 latent 不能混用。[SONIC 实现](https://github.com/NVlabs/GR00T-WholeBodyControl/blob/7f151314d4d1606544bf249d2a7a1cb754c64582/gear_sonic/trl/modules/universal_token_modules.py)、[VLA 接口](https://github.com/NVlabs/GR00T-WholeBodyControl/blob/7f151314d4d1606544bf249d2a7a1cb754c64582/docs/source/tutorials/vla_inference.md)

第一版用连续参考作为生成与检查对象，经原生参考编码路径进入固定 SONIC。这样可以分别测量参考是否碰撞、编码是否损失净空、跟踪是否偏离。直接生成 native token 是后续输出空间比较：固定 encoder、quantizer、decoder 和观测配置，明确训练标签是在什么参考状态下编码的，再检查解码与实际执行。任意 token ID 没有欧氏距离，不能直接对整数编号做高斯插值。FSQ 标量坐标可以作为连续建模候选，但重新量化的误差需要单独测量。

如果已有运行成熟的 native-token 系统，则不必为遵循这个顺序拆掉它：增加参考重建与执行日志，作为诊断通路即可。核心要求是能够定位错误。

2. MTC 的价值主要是约束与动作的配对关系。

MTC v1 报告 145 个场景、348 条轨迹、约 2.3 小时记录。它通过 VR 中的尺度处理采集人体参考，再重定向至 G1；论文指出场景无关的重定向与姿态估计噪声等限制。其生成时的二维可达性检查、参考几何检查和机器人动态执行是不同证据。[MTC，III–V](https://arxiv.org/html/2603.05993v1)

因此应分配不同数据角色：通用 motion 教身体连续性、协调与步态；MTC 类配对数据教环境如何改变动作；场景几何和候选 probe 教可通行性；固定 tracker 的真实 rollout 教执行误差和失败分布。不要把纯 motion 的数量当成场景条件监督的数量。

尤其不能指望从 motion 唯一反推出 scene。相同下蹲可能由低梁、任务偏好、身体状态或动作风格造成。即使知道动作无碰撞，它主要约束身体扫过的空间应当容得下身体，并不能确定旁边障碍物的真实形状。因此 Motion2Scene 若作为预训练任务，应预测可支持的关系或带不确定性的几何假设，不能把完整场景重建当作可辨识的真值任务。

普通的“配对 scene–motion 为正，随机换一个 scene 为负”的 InfoNCE 也不充分：同一动作在许多场景中都可能可行。负例必须有已验证的不兼容关系，否则网络会学场景身份，并处罚有效的替代组合。

推荐的数据层次如下。未知字段明确缺失，不用猜测补齐。

| 层次 | 至少保留的字段 | 用途 |
|---|---|---|
| Scene | scene_revision、几何、物理尺度、坐标变换、允许支撑面、layout_family | 查询可通行性，按场景家族划分 |
| Episode | source_ancestry、actor/session、human_reference、robot_reference、原始时间戳、目标来源 | 保留重定向与采集来源 |
| Observation | sensor_pose、内外参、观测时间、占据/空闲/未知、置信度 | 形成部署可用输入 |
| Execution | 实测本体状态、发出命令、native token（若有）、tracker 版本、接触/跌倒/延迟 | 与参考分开测量 |
| Event | prepare_start、constraint_interval、whole_body_exit、recovery_end、事件依据及可信度 | 覆盖因果上下文 |
| Counterfactual | scene_edit 或 motion_edit、parent_id、几何标签、执行标签、验证预算 | 测量是否需要改变动作 |

原始记录、canonical episode 和窗口索引分层保存；地图按 scene revision 缓存，窗口不重复复制整个 mesh。先按原始 episode、场景家族与镜像祖先划分，再切窗口。高帧率记录的重叠窗口不能当作独立演示。

人体视点不是机器人视点，人体参考历史也不是实测机器人状态。没有 rollout 时，可做明确标注的参考历史预训练；进入闭环研究后必须补测量历史与访问状态修正。全场景用于 oracle 标签或上限实验，因果地图用于部署输入；未知空间不能被默认为空。

3. 用可通行动作集合定义压缩应保留的信息。

给定候选动作 M、身体部位 b 和物理时刻 k，定义对禁止碰撞表面的净空

$$
d_{b,k}(M,S)=\min_{x\in\mathcal B_b(M_k)}\phi_S(x).
$$

其中 B 是身体表面，不只是关节中心；允许的脚地支撑需要独立处理。离散表面点和时间采样只给近似标签，窄间隙必须提高精度或检查连续扫掠。

令 Z=E_S(S_obs,h,g) 是压缩场景表示。用可追溯的候选动作 probe 训练关系查询器 R(Z,M)，输出分部位净空、几何是否足够可见、支撑相容性。几何标签来自可靠的 mesh/距离查询；执行风险来自 tracker rollout，两种输出不共用一个含混的 valid 标签。

压缩质量至少要测两个不同指标：净空数值误差，以及把不安全动作误判成安全动作的比例。后者在净空边界附近尤为重要。平均点云重建误差、平均关节误差相同，不意味着这两个指标相同。

一个训练目标是

$$
\mathcal L_{rel}=\mathbb E_{M\sim\mathcal Q}
\sum_{b,k}w_{b,k}\rho\big(R(Z,M)_{b,k}-d_{b,k}(M,S)\big).
$$

Q 应覆盖演示、平滑姿态扰动、不同路线/姿态候选与边界附近样本；不能只查询演示已走过的姿态。w 可提高可靠边界样本的贡献，但权重上限、标签可信度和普通样本比例都需要验证。部分观测下，对未观察区域预测未知或分布；不能把全场景的唯一距离标签强塞给看不见障碍的学生。

进一步，可定义有限候选集合 Q 上的决策失真。令 J(M,S) 为预先声明的候选代价，J_hat 为压缩表示的估计；如果对所有候选都有 |J_hat-J|≤epsilon，则基于 J_hat 选出的 M_hat 满足

$$
J(\hat M,S)-\min_{M\in\mathcal Q}J(M,S)\le2\epsilon.
$$

这是一个直接的代数结论：分别对所选候选和真实最优候选使用误差界，中间使用 J_hat 的最小性。它只对这个有限集合、这个代价和真实成立的一致误差界有效，不是闭环安全保证。但它说明为什么“压缩后还能不能选对动作”比“还原了多少 scene 点”更贴近任务。

训练不必估计互信息。固定 token 数、维度、精度以及局部几何额外读取量，用上述任务失真比较 encoder 即可。没有随机化/量化等明确编码模型时，把一个普通确定性 MLP bottleneck 宣称为严格的信息论压缩是不充分的。

若后续加入 motion codec，测量 M 与 D(E(M)) 在相同场景中的净空变化。为狭窄边界保留小的局部 residual 是可研究选项，但不能用多给 residual tokens 的方法冒充等容量优势。

4. 把压缩、感知和执行误差放进同一净空预算。

考虑一个给定物理时刻的身体表面。若场景距离场误差在查询区域内有上界 epsilon_S，运动压缩造成的身体表面 Hausdorff 偏差至多 epsilon_M，执行身体相对解码参考的偏差至多 epsilon_T，那么在真实有符号距离函数为 1-Lipschitz、坐标与表面对应一致的条件下，保守地有

$$
d_{exec}\ge\hat d_{represented}
-\epsilon_S-\epsilon_M-\epsilon_T.
$$

其中 d_hat_represented 必须对应压缩误差发生前的名义表示；若已经对解码后的完整 mesh 做精确查询，则不应再次扣除同一 codec 误差。证明只使用距离函数的 Lipschitz 性和集合偏差的三角不等式。若需要单独计算陈旧观测/时延引起的相对位移，可加入有根据的 v_rel,max L 项；若 tracker 偏差已包含时延，不要重复计数。

这个预算的研究意义是：压缩目标应由任务剩余净空决定。一个概念性例子是名义净空 20 mm，而场景、codec、跟踪的保守误差之和是 35 mm，那么“均方误差很低”仍不能支持该候选稳健可执行。这些数值仅用于解释，没有来自机器人实测。

实践中这些误差常只有验证集分位数，不能把分位数相加后宣称确定性保证；联合概率还需要校准、相关性与分布转移分析。第一轮报告经验失效率和误差预算即可。

这个分析也给出一个停止开发新 attention 的条件：若 oracle 全地图与高精度参考仍在同样位置失败，而误差主要来自 SONIC，就应先处理 tracker 的能力或参考可执行范围。

已有实验也提醒我们不能把执行层当作透明模块：PASSAGE 在其模拟消融中，把感知增强 tracker 换回基础 tracker 后，无接触成功率从 70.3% 降到 18.4%。这是该系统、场景与替换方式下的组件结果，不是 SONIC 的性能预测；它支持先诊断执行层的重要性。[PASSAGE，IV-D](https://arxiv.org/html/2609.18732v1)

5. “极限瞬间”的操作化定义是动作选择开始失去余地。

最小净空只是候选事件信号。真正需要监督的是何时开始准备，以及何时才能结束姿态保持。事件窗口必须覆盖准备、受限通过、全身离开和恢复。低梁后的肩部与后脚仍可能处于约束中，头部出梁不能作为唯一退出判据。

建议比较三种事件选择器：单纯小净空；小净空加姿态/支撑变化；反事实调整延迟敏感度。第三种是本文建议深入研究的假设。

对一条已合格参考，在相同初始状态与相同约束下，构造“推迟改变姿态/落脚”的替代参考，再用相同修复器和预算重新求解、验证。令 delta 表示调整延迟，可定义

$$
A_e(\delta)=J(M_e^{delay(\delta)},S)-J(M_e,S).
$$

只有两者都经过规定验证，这个量才有明确含义。若延迟参考失败而原参考成功，说明该窗口含有当前参考族中的关键调整时机。它不证明任何其他控制器都无法恢复，因此不要称为全局的最后可救时刻。

先用便宜的几何扫描筛候选，再为部分候选做动态验证；记录额外标注/仿真成本。直接时间平移几帧造成关节速度不连续的失败不能被解释成几何决策信息。

更有辨识力的数据是对照组：同一目标/起始状态，逐步改变梁高或侧隙；同一场景，改变速度或步态相位；同一局部观测，改变可观测的目标。若两种动作都可行，标签是偏好或代价差，不是可行/不可行。场景修改使旧动作碰撞时，旧动作只能成为负例，除非重新获得有效正例。

事件 oversampling 有意改变训练分布，不等于无偏训练。先比较 uniform 与 uniform/event mixture，匹配训练窗口总数、去重轨迹和计算量；对照采样匹配速度、动作幅度和基础难度，避免把“更大动作”误认为“更有因果信息”。高 loss、低净空和高信息量不是同义词。

6. Attention 查询应围绕未来身体扫过的区域。

3D FlowMatch Actor 提供了动作与视觉 token 在共同三维坐标下交互的先例。TAGA 已研究选择与运动有关的局部地形；LINGO 已有当前与前方场景编码。因此新设计的区别必须体现为测量到的决策信息保留，而不只是使用 cross-attention。[3D FlowMatch Actor](https://arxiv.org/html/2508.11002v1)、[TAGA](https://arxiv.org/html/2606.05880v1)、[LINGO](https://arxiv.org/html/2410.03187v1)

建议保持两个场景通路：固定容量的全局路径上下文，以及围绕候选身体扫掠区域的细节。局部 scene token 保留位置、表面法向、可见性、时间和置信度。不要只存一个 room embedding，也不要完全丢弃局部区域之外的备选路线。

对未来物理时刻 k、部位 b，先由 motion feature 形成 query。依据当前模型的 clean-motion estimate，以 FK 得到该部位表面或 capsule 的预计区域 B_hat，并对相邻物理时刻形成 swept tube。一个可实现的 score 是

$$
e_{kbj}=\frac{Q(h_{kb})^TK(f_j)}{\sqrt d}
+\beta_\phi\big(p_j-\hat p_{kb},\ n_j,\Delta t_k,\mathrm{visibility}_j,\mathrm{age}_j\big).
$$

邻域查询使用 tube 与 scene patch 的距离，而非只看关节中心。额外的查询半径反映预计跟踪偏差或遮挡不确定性；它仍是经验设计，需要测试。部位间随后做 whole-body attention，时间上做 temporal attention，避免头、肩和双脚局部避障互相冲突。

FM 高噪声时 FK anchor 不可靠。第一步依赖测量历史、目标和宽范围几何；后续逐渐增加模型自身预测驱动的局部查询，并始终保留全局路径。可通过一次不反传的预测构造训练 self-conditioning，或从先前迭代取 anchor；不能训练时拿真实未来位置裁剪 ROI，而部署时要求模型自己预测。

用观测年龄直接遗忘场景也可能出错。低梁从相机视野消失后仍可能在肩背上方；保留条件应包括全身扫掠关系，而非只按最近图像排序。存在地图位姿漂移时，要一起传播几何位置的不确定性。

不要把 attention 热力图当因果证据。真正的检查是局部几何干预是否改变动作、删除相关 patch 是否损害相应行为，以及无关几何变化是否导致不必要的姿态改变。几何访问成本、感知缓存与 query 开销要进入延迟账本。

7. FM 先使用标准目标，再逐项改变源分布和约束。

采用噪声在 0、数据在 1 的约定：

$$
X_\tau=(1-\tau)X_0+\tau X_1,\quad
\mathcal L_{FM}=\mathbb E\|v_\theta(X_\tau,\tau,C)-(X_1-X_0)\|^2.
$$

推理积分 dX_tau/dtau=v_theta，从所声明源分布采样 X_0。tau 是生成时间，k 是动作物理时间；向量场不是物理关节速度。[Flow Matching](https://arxiv.org/abs/2210.02747)

这套形式对本任务有三种用途：保留多个通过策略的分布；共同生成一段相互协调的运动；允许更换可采样的结构化源分布。扩散模型也能实现多模态、条件生成和补全，FM 并不独占这些能力。推理速度需测实际 wall-clock 与成功率，不能用一种方法的默认大步数对比另一种方法的调优小步数。

建议的首个 FM 专门比较是 iid Gaussian 与时间相关 Gaussian source：

$$
X_{0,F}=\mu_F(C)+L_T\epsilon,\qquad
\epsilon\sim\mathcal N(0,I),\quad L_TL_T^T=K_T.
$$

F 为可修改后缀。K_T 可以是带小对角项的时间核，或可高效采样的平滑基与全维噪声组合。只在归一化后的连续变量上构造；旋转需使用一致的表示和解码。保持全维后缀支持，避免过强平滑消除快速抬脚/姿态调整。mu 从零开始，随后才比较上下文/检索生成的均值。

ConFlow 已研究 conditional GP source、约束训练和负例，因此“用 GP 替代白噪声”应作为借鉴与基线，不能当作原创主张。它研究的条件边界不能直接照搬成未知的人形终止关节姿态：坐标导航目标不等于未来全身 pose。[ConFlow，IV](https://arxiv.org/html/2607.14424v1)

前缀 P 在所有生成阶段保持不变，FM loss 只覆盖自由后缀，按有效坐标归一化。随机化训练前缀长度以覆盖实际延迟，并用部署采样源分布训练。Training-Time RTC 是直接参考；初始训练中的干净演示前缀只是起点，后续需要处理实际前一轮生成前缀和测量状态的偏差。[Training-Time RTC](https://arxiv.org/html/2512.05964v1)

不要把“沿用上次预测作为 X_0”当作免费的 warm start：若训练只见独立 Gaussian，它改变了推理源分布。可以训练混合源或一致的前缀/后缀条件方案，但必须把同样规则用于训练和推理。旧 chunk 在新障碍信息出现后也可能失效。

对几何约束，用近数据阶段的端点估计

$$
\hat X_1=X_\tau+(1-\tau)v_\theta(X_\tau,\tau,C)
$$

或完整采样结果计算。高噪声端点均值可能把左绕、右绕两个安全模式平均到障碍中央，因此不要把每个 noisy state 的碰撞都当作真实错误。

可在 baseline 后加入

$$
\mathcal L=\mathcal L_{FM}+\lambda_{rel}\mathcal L_{rel}
+\gamma(\tau)\lambda_{geom}\mathcal L_{geom}(\hat X_1,S).
$$

gamma 初始只在近数据阶段启用；逐项检查采样多样性、梯度尺度和闭环收益。加入几何正则会改变学习目标，应明确它是有意偏向可行性的优化。

HardFlow 把约束主要放在生成过程的最终样本，可作为最终候选 refinement 的方法参照。SafeFM、UniConFlow 和 CASF 则提供 barrier/QP/metric 等其他路径；它们对所建模系统的约束结论不能自动覆盖浮动基座、多接触与 SONIC 跟踪误差。[HardFlow](https://arxiv.org/html/2511.08425v1)、[SafeFM](https://arxiv.org/html/2504.08661v1)、[UniConFlow](https://arxiv.org/abs/2506.02955)、[CASF](https://arxiv.org/html/2602.15567v1)

如果采取 refinement，选择整条候选后共同优化 root、姿态、时间与边界衔接，不要只把碰撞关节单独推开。记录优化失败、超时和分布偏移；几何可行不意味着动力学可行。

8. 两个容易改变数学含义的“改进”。

第一，若给 FM 回归加矩阵权重 W，并且 W 依赖真实未来动作 X_1，那么在固定 (X_tau,tau,C) 下，其总体最优解通常变成

$$
v^*=(\mathbb E[W\mid X_\tau,\tau,C])^{-1}
\mathbb E[W(X_1-X_0)\mid X_\tau,\tau,C].
$$

这一般不再等于标准 FM 的条件均值速度。若 W 是只由网络已有条件/当前状态决定、固定且正定的矩阵，则可保持相同点态总体最优解；有限容量训练仍可能不同。由真值净空产生的权重不是无代价的几何 metric。可以使用，但要承认训练分布或目标已经改变。

第二，若对每个物理帧使用不同生成进度 r_k(tau)，路径为

$$
X_{\tau,k}=(1-r_k(\tau))X_{0,k}+r_k(\tau)X_{1,k},
$$

则目标速度应为 r'_k(tau)(X_1,k-X_0,k)。不能改了噪声日程仍沿用原 target。r_k 的条件也必须在部署可得，不能用真值事件位置暗示未来。第一轮不建议加入这种额外复杂度，除非实验表明统一日程确实是瓶颈。

9. 一个可实施的预训练与闭环顺序。

| 阶段 | 输入及目标 | 通过条件 |
|---|---|---|
| 接口检查 | 少量不同类型参考 → 固定 SONIC，记录执行与净空 | 区分重定向、接口、tracker 失败；确定支持的动作范围 |
| Motion prior | 合格通用运动；未来预测、masked completion、prefix FM | 有效动作连续性；无场景样本不加场景监督 |
| Relation pretraining | 场景、候选 probe、几何标签 | held-out geometry 下保持净空与兼容性，比较解析几何基线 |
| Paired FM | MTC 类因果观测、目标、合格参考 | 简单模型能闭环完成目标任务，未用未来真值裁剪 |
| 机制比较 | 固定预算替换压缩监督、attention 或事件采样 | 分别识别信息、时机与额外计算的影响 |
| 执行适配 | 规划器实际访问状态、同预算纠正/风险数据 | 完整任务表现改善，未只挑成功 replay |

先假设导航输入为数值目标、传感器为可形成因果三维地图的 depth/LiDAR。若最终只有 RGB，需要明确深度估计与度量尺度来源；如果是语言目标，在上游增加语义目标解析，不应让语言 backbone 掩盖最初的几何学习问题。

工程起点可用 6–8 层 Transformer、body groups、一个简单三维 encoder；这些不是调优结果。预测时域依据“感知/规划延迟 + 姿态准备时间 + 约束覆盖”选取，并比较多个时域。必要时在短时动作之外增加更远处低带宽约束上下文，而不是把远处导航目标当成短 chunk 的硬终点。

推理时缓存 scene encoder 特征，只更新便宜的身体关系查询。生成少量候选、用可见几何与校准后的执行风险选择，执行短前缀后重新观测。候选多样性不是 epistemic uncertainty，不能直接当风险置信区间。没有合格候选时需要在执行能力范围内减速/停止或获取观测，而不是反复挑选最低的未经校准分数。

10. 决定是否值得继续的实验。

先做表示实验，再做大规模生成训练。在相同容量下，用相同候选库比较普通场景压缩和关系监督压缩；如果后者不能更好地保持边界附近动作兼容性，则没有足够理由期待把它放进 FM 会解决问题。

最小闭环实验采用固定数据、tracker、候选数、推理预算与同预算调参。以完整任务成功为主指标：到达目标、全身离开障碍区、无禁止接触/跌倒，并完成规定恢复/停止。blocked-scene 的安全停止应单列，不能与通行成功混合。

| 问题 | 比较 | 可能推翻假设的结果 |
|---|---|---|
| 需要生成模型吗？ | 检索 + 几何编辑 + 同一 SONIC，对照基础 FM | 小数据下检索更好，说明先扩充候选/边界数据更划算 |
| 压缩保住了什么？ | 同容量普通编码 vs 关系监督；共同 probe 与选择器 | 只有更大容量有效，关系机制解释不成立 |
| 是否真在提前准备？ | uniform、最小净空、延迟敏感事件；等训练 exposure | 只在训练布局有效，可能是场景记忆或时刻泄漏 |
| 几何查询是否必要？ | 普通交互 vs body-relative；同 token/计算预算 | oracle 地图也无改善，应检查生成/执行瓶颈 |
| FM 源分布是否有用？ | iid、GP/相关源；共同 backbone 和近似延迟 | 少步误差改善但闭环不变，贡献限于采样而非穿越 |
| 是编码还是控制失败？ | 未压缩参考、codec 解码参考、实际执行三者比较 | tracker 主导误差，暂缓新 codec/attention |

核心机制实验可先用 2×2：关系监督开/关 × 事件采样开/关，保留同一个 attention backbone。等主要假设成立后再研究局部查询或源分布，避免一次增加太多模块无法解释。

诊断指标包括净空安全误判率、压缩新增碰撞率、姿态调整提前量、全身退出前恢复过早率、跟踪误差、端到端延迟分位数。报告 deployed selector 与 best-of-K oracle 分开结果。测试按场景家族、梁高/侧隙边界、遮挡、速度/相位和跟踪扰动分组；训练窗口不是置信区间的独立样本，统计需保留场景与原始轨迹的聚类结构。

只有在“表示改善 → 行为对几何干预产生合理响应 → 完整闭环收益”这几个联系得到证据后，才支持机制主张。若整体系统有效但无法隔离哪一个组件起作用，可以报告系统价值，不能把它写成已经证明的信息论解释。

建议当前研究问题写为：

> 在有限表示与推理预算下，以候选动作兼容性为预训练目标、覆盖动作准备期的场景—运动表示，是否比重建驱动的压缩更能保持狭窄环境中的全身可通行性，并提高固定 tracker 下的完整闭环穿越成功率？

这个问题允许结果为否，也明确了 FM 的角色：它负责从信息充分的条件中生成多个协调的连续运动解；表示学习负责保留决定动作选择的信息；实际 tracker 和闭环验证决定这些解能否执行。
